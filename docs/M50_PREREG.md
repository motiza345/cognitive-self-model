# M50 pre-registration: a cost-aware metacognitive gate on mixed verifiable tasks

Status: accepted by the author on 2026-10-16; binding from the commit that adds this file, which precedes any M50 data. Parameters below are final unless the pilot shows a design flaw (one amendment is allowed, pushed before collection).

## 1. Question

Does a module outside the language model, which converts the model's own answer probability into answer / verify / abstain decisions using per-scope calibration learned online (cognitive layer 0.2.1), beat simple policies, and does per-scope calibration add value over a single global calibration? Is a hidden-state probe a better confidence source than the answer log probability?

## 2. Setting (fixed)

- **Model:** `Qwen/Qwen2.5-3B-Instruct`, revision `aa8e72537993ba99e69dfaafa59ed015b17504d1`, fp16, greedy decoding, Colab GPU, batch generation allowed (results must not depend on batch size; the manifest records it).
- **Prompts:** one fixed user message per task, passed through the model's default chat template (no explicit system message is supplied; the Qwen template inserts its default system message, identical for all items), reply with the answer only: `Compute A x B. Reply with only the integer.`, `Compute A + B. Reply with only the integer.`, `Sort ascending: x1, x2, ... Reply with only the sorted numbers separated by commas.`
- **Tasks and levels (candidates):** `mul_n1` (n-digit times one digit, n = 2..10), `add_nn` (n-digit plus n-digit, n = 3..15), `sort_n` (n distinct two-digit integers, n = 3..12). Correct means exact match with the true answer after stripping spaces (integers: commas removed; sort: comma-separated list of integers, whitespace stripped). Unparsable means wrong.
- **Scope** = (task, level). **Verifier tool** = the exact checker; calling it reveals the true answer.
- **Payoffs:** answer +1 if correct, -1 if wrong; abstain 0; verify +0.7 (the answer is replaced by the verified one at cost 0.3). Expected utilities given a probability p of being correct: 2p - 1, 0, 0.7.
- **Confidence signals stored per generation:** token log probabilities (end-of-sequence excluded) and their sum; two hidden-state vectors: `h_prompt` (residual stream after the final prompt token at layer 18), `h_answer` (mean over generated tokens of the last-layer hidden state). Stored as float16 arrays plus a manifest.

## 3. Conditions

- **Natural:** the generations as they are.
- **Implanted (positive control):** the same generations with a seeded post-hoc corruption of one scope family: for every `sort_n` item, with probability 0.3 (seed 50003) the delivered answer is treated as corrupted and therefore wrong; token log probabilities and hidden states are unchanged (the corruption is invisible to them and visible only through verification). The corruption flags are generated by the analysis script from the seed.

## 4. Procedure

1. **Pilot** (seed 50002): 40 problems per candidate level for each task (about 1280 generations). Discarded afterwards except for the gate and the level choice.
2. **Level choice per task (fixed rule):** over windows of 4 contiguous levels, maximize `gap_hat = mean over the window's levels of max(2p - 1, 0.7) - max(2*pbar - 1, 0.7)` (p = pilot accuracy, pbar = window mean), subject to at least 2 levels with pilot accuracy in [0.25, 0.75]; ties go to lower levels. If a task has no qualifying window it is dropped (at least 2 tasks must remain, else the whole evaluation is `NOT_INFORMATIVE`).
3. **Gates (computed on the pilot data of the chosen windows, written to `reports/m50_pilot/gates.json` and committed before collection):**
   - **G-ceiling:** instance oracle utility minus always-verify utility is at least 0.15.
   - **G-variance:** at least 5 scope-levels with pilot accuracy in [0.25, 0.75].
   - **Sample size rule:** TEST items per scope-level = 40. If the pilot-based standard error of the difference (scoped layer minus the best simple policy, estimated by running the layer on pilot data split 50/50) exceeds 0.015, TEST items per scope-level = 80.
   If a gate fails, the affected condition is labelled `NOT_INFORMATIVE` and collection does not start.
4. **Collection** (seed 50001 for the problem generator): per chosen scope-level CAL 100 and TEST 40 (or 80) problems, disjoint from each other and from all earlier pools (tests of disjointness against M34a pools and the pilot). Resumable cache, one JSON line per generation, hidden states in an `.npz`, manifest with model revision, dtype, device, library versions, git commit, cache hashes, runtime.
5. **Analysis** (offline, once, on a clean tree, committed before collection): runs every arm below and writes `reports/M50_REPORT.md`.

## 5. Arms (all decisions are made by the module, not by the model)

| id | arm | definition |
|---|---|---|
| A1 | always answer | act on every item |
| A2 | always verify | verify every item |
| A3 | random verify | verify each item with probability q, else answer; q = the verify rate of A6 on TEST (matched budget), seed 50004 |
| A4 | raw confidence | p = exp(sum of token log probabilities), no calibration |
| A5 | global calibrated | cognitive layer 0.2.1 with a single GLOBAL claim |
| A6 | scoped layer | cognitive layer 0.2.1 with one claim per scope-level (CalibrationRule min_each 15, epsilon 0.05, utilities as above, exploration and learning mode as built) |
| A7 | track record | per scope-level accuracy `(correct + 1) / (n + 2)` learned online by the layer in `base_rate_only` mode |
| A8 | probe on `h_prompt` | L2 logistic regression with scope one-hot, regularization chosen by 5-fold cross-validation on CAL only, probability used with the same decision rule |
| A9 | probe on `h_answer` | same |
| R1 | instance oracle (reference) | knows whether the answer is correct |

Layer arms learn from the CAL pool as an online stream in shuffled order (8 shuffle seeds 0..7, results averaged per item), are then frozen, and are scored once on TEST, as in `layer/scripts/replay_m34a.py`. Probe arms are trained on CAL and scored once on TEST. The learning-phase utility of the layer arms is reported as the cost of learning.

## 6. Statistics

Unit: TEST item. Paired percentile bootstrap, 5000 draws, seed 23001, 95% interval, resampling items (scope-levels are fixed strata). Four hypotheses in two conditions; the **primary** test is H-A in the natural condition. The labels below are defined on the 95% intervals as written. For the seven secondary tests the analysis also reports Holm-adjusted bootstrap p-values (two-sided, from the same 5000 draws) and marks a secondary label that is not Holm-significant at 0.05; the label itself is not changed.

## 7. Hypotheses and labels (exhaustive)

Let `U(x)` be mean TEST utility.

- **H-A (the gate works).** `dA = U(A6) - max(U(A1), U(A2), U(A3))`. `A_SUPPORTED`: `dA >= 0.03` and lower bound > 0. `A_WEAK`: lower bound > 0 and `dA < 0.03`. `A_NOT_SUPPORTED`: otherwise.
- **H-B (calibration matters).** `dB = U(A6) - U(A4)`. `B_SUPPORTED`: `dB >= 0.02` and lower bound > 0. `B_WEAK`: lower bound > 0 and `dB < 0.02`. `B_NOT_SUPPORTED`: otherwise.
- **H-C (scoping matters).** `dC = U(A6) - U(A5)`. `C_SUPPORTED`: `dC >= 0.02` and lower bound > 0. `C_WEAK`: lower bound > 0 and `dC < 0.02`. `C_NOT_SUPPORTED`: otherwise.
- **H-D (probe versus log probability).** `dD = max(U(A8), U(A9)) - U(A6)`. `PROBE_BETTER`: `dD >= 0.02` and lower bound > 0. `LOGPROB_BETTER`: `dD <= -0.02` and upper bound < 0. `UNRESOLVED`: otherwise.
- **Gate failure** in a condition: all four labels of that condition are `NOT_INFORMATIVE`.
- **Positive control (implanted condition):** H-C must be `C_SUPPORTED`. Otherwise the implanted condition is labelled `POSITIVE_CONTROL_FAILED` and no scoping conclusion is drawn from either condition; the library is checked for a defect first.

Every combination of the four labels in each condition is a valid recorded outcome; no outcome is left without a label.

## 8. Decision rules (fixed now)

| outcome | action |
|---|---|
| natural `A_SUPPORTED`, `B_SUPPORTED`, and implanted `C_SUPPORTED` | The layer is useful as a calibrated gating module; write it up; plan 0.3 |
| natural `A_SUPPORTED`, natural `C_NOT_SUPPORTED`, implanted `C_SUPPORTED` | Global calibration is enough on natural workloads; per-scope calibration helps only against agent-specific failures; report both |
| natural `A_SUPPORTED`, implanted `POSITIVE_CONTROL_FAILED` | Check the library for a defect, repair once under a documented amendment, and re-analyse the same cache |
| natural `A_NOT_SUPPORTED` or a failed gate | Report as negative or inconclusive; publish the library and the replay; stop |
| `PROBE_BETTER` | Report that hidden-state probes beat the log probability in this setting; this is reported in the paper but does not change the library decision |

## 9. Not claimed

No claim about self-awareness or introspection; no claim about models other than `Qwen2.5-3B-Instruct`; no claim about tasks other than the three used; the implanted condition is a simulation of an agent-specific failure, not evidence that such failures are common; the verifier is assumed exact and its cost fixed.

## 10. Amendment and stop rules

One amendment at most, pushed before collection. No threshold, arm or label is changed after TEST data exist. If a gate fails, the condition is closed with the label above. The evaluation is closed after the single analysis; follow-up work needs a new pre-registration.

## 11. Compute and cost (estimates, not measured)

Pilot about 12 minutes, collection about 20 to 40 minutes (hidden-state extraction adds overhead), analysis on CPU. About one Colab GPU hour in total.

## 12. Deliverables

`docs/M50_PREREG.md` (this file), `scripts/m50_pilot.py`, `scripts/m50_generate.py`, `scripts/m50_analyze.py`, tests with a mock model, `docs/M50_RUN.md` (Colab cells), later `reports/M50_REPORT.md` and an appended entry in `reports/CLAIM_LADDER.md`.
